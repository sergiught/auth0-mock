There are two good ways to run the mock in automated tests.

- **Testcontainers.** Each test suite starts its own mock on a random port and stops it at the end. It works the same on your laptop and in any CI that has Docker.
- **A GitHub Actions service container.** One mock runs for the whole job on a fixed port. Use it when several steps share one mock.

The examples on this page are the real test files from the repository's `examples/testcontainers` folder. CI runs them, so they do not drift from the code you see here.

## Testcontainers

Each test does the same things, in this order:

1. Start the image and wait for `GET /healthz` to return 200.
2. Build the base URL from the container host and the mapped port. Never hard-code `localhost`, because the Docker host can be remote.
3. Stub `GET /api/v2/users/auth0|123` with `POST /admin0/expectations`.
4. Get a token from `POST /oauth/token` with the client credentials grant.
5. Call the stubbed endpoint with the token.
6. Check the response body.
7. Check the token: its signature against the mock's JWKS, its `iss`, and its `aud`.
8. Stop the container.

The container needs three settings. `ADMIN_ALLOW_REMOTE=true` is needed because the image listens on all interfaces so Docker can reach it, and the mock refuses to start that way unless you allow it, since `/admin0` has no authentication. `HTTPS_ADDR=off` turns off the TLS listener, so the tests use plain HTTP and need no certificate. `ISSUER_URL=auto` makes the mock use the address of each request as the issuer, which is right for a random port.

With `auto`, a token only verifies at the address it was minted at. If your tests and your app reach the mock at different addresses, the app rejects the token, the same way one Auth0 tenant rejects another's tokens.

:::note
The token check needs `ISSUER_URL=auto`, which ships in release 0.234.0. With an older image the test fails at that check.
:::

Note the request path `/api/v2/users/auth0%7C123`. The stub is registered with a raw `|`, but some HTTP clients, such as Java's `URI.create`, reject a raw `|` in a path. Sending `%7C` works everywhere.

### Pin a tag

The examples use `ghcr.io/sergiught/auth0-mock:latest` so they run as written. In your own suite, pin a release so a new version cannot change your tests unexpectedly, for example `ghcr.io/sergiught/auth0-mock:0.234.0`.

## GitHub Actions service container

Use a service container when one mock serves every step in a job. The runner starts the image before the first step and waits for the health check to pass. Steps reach the mock at `localhost:8080`.

Without `ISSUER_URL`, the issuer defaults to `https://localhost:8443/`, so the `jwks_uri` in the discovery document points at the HTTPS listener, which this recipe turns off. If your app verifies tokens, set `ISSUER_URL=http://localhost:8080/` (or `auto`, from release 0.234.0). The recipe itself only calls the stub, so it needs neither.

The health check uses `wget`, which the image includes.
